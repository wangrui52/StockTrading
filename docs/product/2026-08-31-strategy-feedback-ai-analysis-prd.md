## 一、背景和目标

### 1.1 需求背景

当前系统已经完成“同步数据 → 指标与信号 → 候选股 → 详情/自选/提醒 → 规则报告”的确定性链路，但候选结果停留在“当日为什么入选”，没有回答：

- 候选在未来第 1、3、5 个有效交易日表现如何；
- 哪个规则版本、市场环境或信号组合更稳定；
- 参数调整是否经过无未来数据泄漏的历史验证；
- AI 生成的解释引用了哪些已验证事实，失败时能否安全降级。

这导致候选结果无法形成长期可评价的数据资产，规则调整主要依赖主观观察。对标项目提供了“推荐结果回填”和“量化数据后置 AI 解读”的启发，但其 LLM 直接调整权重、CSV 状态和简化回测不能满足当前系统的批次隔离、规则版本化和可追溯要求。

### 1.2 项目收益

本期目标是将一次性筛选升级为可验证、可对比、可审计的策略反馈闭环，同时在不削弱确定性规则的前提下提供可选 AI 解读。

| 目标 | 成功标准 |
|---|---|
| 候选效果可评价 | 到期候选的 T+1/T+3/T+5 评价覆盖率不低于 99%；未完成评价有明确原因 |
| 结果可追溯 | 每条评价可追溯到候选、源批次、评价批次、交易日和规则版本 |
| 实验可信 | walk-forward 回放不得使用决策时点之后的数据；输出样本量、基准、费用、最大回撤和稳定性 |
| 生产规则受控 | AI 或离线算法只能创建草稿实验，未经人工批准不得成为生产规则版本 |
| AI 事实受控 | AI 报告中事实性结论的证据引用覆盖率为 100%；无法引用的内容不得作为结论输出 |
| 降级可靠 | 未配置模型、超时、限流、格式错误时，既有同步、筛选、提醒和规则报告保持可用 |

### 1.3 覆盖用户

仅面向项目所有者本人，维持单用户、本机 Web 工具定位。不新增注册、登录、角色、多租户和公网发布能力。

### 1.4 方案简述

方案分为三层：

1. **确定性评价层**：在新交易日批次激活后，为历史候选计算 T+1/T+3/T+5 收益及最大有利/不利波动。
2. **策略实验层**：基于冻结规则和历史窗口执行 walk-forward 回放；实验结果先进入影子状态，人工批准后才生成新规则版本。
3. **可选 AI 分析层**：只读取结构化证据包和可追溯外部事实，负责归纳、冲突解释和实验假设，不直接写行情、信号、候选或生产规则。

### 1.5 未来会做什么

- P2 引入政策、行业和公司动态检索，并保存来源 URL、发布时间、抓取时间和引用关系。
- 增加组合级评价、相关性、资金曲线与风险预算，但仍不接实盘。
- 在数据规模与并发需要时评估 PostgreSQL 和任务队列。
- 券商接口、自动下单和收益承诺不在规划范围内。

## 二、名词说明

| 名词 | 定义 |
|---|---|
| 源候选日 T | `candidate_result` 所属数据批次的交易日 |
| T+N | T 之后第 N 个有效交易日，不按自然日计算 |
| 参考价格 | 评价起点价格；默认使用 T+1 不复权开盘价，不使用形成信号当日收盘价假定成交 |
| 评价价格 | T+N 不复权收盘价 |
| 候选评价 | 基于已激活未来批次，对历史候选生成的确定性效果记录 |
| MFE | 评价区间内相对参考价格的最大有利波动 |
| MAE | 评价区间内相对参考价格的最大不利波动 |
| Walk-forward | 只使用当时已经可得的数据，按时间顺序训练/提案并在后续窗口验证 |
| 影子策略 | 只计算和记录结果，不影响看板候选、提醒和报告的实验规则 |
| 证据包 | 由已落库行情、指标、信号、候选和市场环境组成的结构化只读输入 |
| AI 报告 | 在规则报告基础上生成的可选解释版本，不替代确定性报告 |
| 生产规则 | 当前同步管线实际使用并形成 `rule_version` 的规则参数 |

## 三、业务流程

### 3.1 候选评价流程

```text
新日线批次 READY 并激活
  → 查找已到 T+1/T+3/T+5 的历史候选
  → 校验参考日和评价日均存在有效行情
  → 计算收益、MFE、MAE
  → 幂等写入 candidate_outcome
  → 刷新策略效果聚合
  → 页面展示评价进度与缺失原因
```

### 3.2 策略实验流程

```text
用户创建实验 / AI 提出实验草稿
  → 固定基础规则版本、参数、股票池和时间窗口
  → 校验参数白名单与范围
  → 后台执行 walk-forward 回放
  → 输出收益、回撤、换手、样本量和分段稳定性
  → 用户查看并批准或拒绝
  → 批准后创建新 rule_version
  → 先影子运行
  → 用户另行激活生产版本
```

### 3.3 AI 报告流程

```text
用户在个股详情或报告页发起 AI 解读
  → 生成并冻结证据包
  → 可选读取已保存的外部事实包
  → 调用配置的 LLM Provider
  → 校验结构化输出、引用和禁用表述
  → 保存模型/Prompt/输入快照/费用/状态
  → 展示 AI 解读或明确降级为规则报告
```

## 五、详细产品方案

### 5.1 FR-1 候选结果追踪

**功能说明**

- 每条 `candidate_result` 分别生成 horizon 为 1、3、5 的评价记录。
- 评价收益：`(评价价格 / 参考价格 - 1) × 100%`。
- MFE：从参考日到评价日区间内最高价相对参考价格的最大正向变化。
- MAE：从参考日到评价日区间内最低价相对参考价格的最大负向变化。
- 所有价格采用不复权口径，显示时标注价格类型和交易日。

**交互逻辑**

- 候选列表新增“后续表现”列：未到期、已评价、数据缺失三种状态。
- 个股候选详情展示各 horizon 的参考日、评价日、收益、MFE、MAE。
- 未到期显示预计评价交易日；无法确定时显示“等待交易日历更新”。

**数据逻辑**

- 参考日为 T 后第一个有效交易日，参考价格默认为该日不复权开盘价。
- 若参考日停牌或无有效成交，状态为 `UNAVAILABLE`，不得顺延到未知日期伪造可成交价格。
- 评价日使用 T 后第 N 个有效交易日的不复权收盘价。
- 每条记录同时保存源候选批次和用于评价的未来数据批次。

**异常与边界**

- 新股退市、长期停牌、行情缺失分别记录原因，不用 0 填充。
- 同一未来批次重复执行评价必须幂等。
- 历史复权修订不影响不复权评价；来源修订产生新评价版本，不覆盖旧记录。

### 5.2 FR-2 策略效果看板

**功能说明**

展示：候选数、评价覆盖率、正收益占比、平均/中位收益、MFE、MAE、最大回撤近似值，并按规则版本、horizon、日期范围和市场环境筛选。

**交互逻辑**

- 新增“策略效果”页面，默认展示当前生产规则最近 60 个有效交易日。
- 支持切换 T+1/T+3/T+5，比较不同规则版本。
- 样本量小于 30 时固定展示“样本不足，不用于判断策略有效性”。

**数据逻辑**

- 所有统计只使用 `COMPLETED` 的候选评价。
- 正收益占比不称为“胜率”；页面使用“正收益样本占比”。
- 按候选产生时已保存的市场环境分组，不能用未来环境反标历史候选。

**异常与边界**

- 没有足够样本时只展示事实数据，不生成优劣结论。
- 不同股票池或规则口径不可直接合并比较，页面必须显示对比限制。

### 5.3 FR-3 Walk-forward 回放

**功能说明**

- 用户选择基础规则版本、时间窗口、horizon 和费用假设，创建回放任务。
- 每个决策日只能读取该日之前已经存在的行情和规则。
- 输出候选级结果和聚合指标，不模拟自动下单。

**默认约束**

- 参考成交价使用下一有效交易日开盘价。
- 佣金、印花税、滑点均为显式参数；默认值必须在设置页展示，不在文档中硬编码为真实券商费率。
- 停牌、涨跌停或缺失数据导致无法成交时标记 `NOT_EXECUTABLE`。
- 输出至少包含样本量、覆盖率、平均/中位收益、分位数、最大回撤、换手率和基准同期表现。

**异常与边界**

- 不允许选择结束日期晚于当前最新已完成交易日。
- 历史数据不足、费用参数非法或规则版本缺失时拒绝启动。
- 任务中断可重试，但同一实验版本的结果不可部分覆盖。

### 5.4 FR-4 策略实验管理

**功能说明**

- 实验来源包括人工创建、确定性参数搜索和 AI 提案。
- 状态：`DRAFT → VALIDATING → VALIDATED`，随后进入 `APPROVED` 或 `REJECTED`；已批准实验可进入 `SHADOW`，运行失败进入 `FAILED`。
- `APPROVED` 只表示允许生成规则版本；生产激活需要单独确认。

**交互逻辑**

- 实验列表显示基础规则、参数差异、窗口、状态和关键指标。
- 审批页并列显示基础规则与实验规则，不允许只展示收益较好的区间。
- 批准与激活均要求二次确认，并写入操作日志。

**数据逻辑**

- 参数必须在白名单中，数值有限、非负且位于定义范围。
- 权重类参数归一后合计 1；单次变化默认不超过配置上限。
- AI 不能直接写 `rule_version`，只能提交 `DRAFT` 实验。

### 5.5 FR-5 市场环境快照

**功能说明**

每个数据批次生成市场环境证据，至少包括主要指数趋势、上涨/下跌家数、全市场成交额、候选覆盖率和数据完整率。板块强弱在来源和字段完成 Spike 后启用。

**边界**

- 只使用该批次可见数据生成，不回填未来标签。
- 缺少板块或市场宽度时保留空值和原因，不由 AI 推测。
- 市场环境用于分组统计和报告上下文，不直接覆盖个股规则结论。

### 5.6 FR-6 AI 结构化报告

**功能说明**

在现有规则报告之外新增可选 AI 解读，输出：事实摘要、正向证据、风险与冲突、需要继续观察的条件、数据缺口和免责声明。

**输出约束**

- 每个事实结论必须绑定至少一个证据 ID。
- 禁止“买入、卖出、必涨、目标价、收益保证”等表述。
- AI 不得自行抓取行情或重算指标。
- AI 报告必须显示模型、生成时间、源批次、规则版本、Prompt 版本和降级状态。

**异常与边界**

- 未配置模型时入口显示“未启用 AI 解读”，规则报告正常使用。
- 超时、限流、格式不合法、引用缺失时不保存成功报告，展示错误和重试入口。
- 同一证据包重复生成产生新版本，不覆盖历史报告。

### 5.7 FR-7 LLM Provider 设置

**功能说明**

- 支持 OpenAI 兼容 Provider；首期只要求一个生产 Adapter 和一个测试 Adapter。
- 设置项包括启停、Provider、模型、超时、最大重试、单次 Token 上限和日预算。
- 密钥只允许通过服务端环境变量配置，页面只显示是否已配置。

**边界**

- 修改模型设置不修改历史 AI 报告。
- 达到日预算后停止新生成请求，不影响确定性功能。
- 不在前端、日志、数据库报告正文中保存密钥。

### 5.8 FR-8 审计与运行记录

- 每次 AI 生成保存请求状态、模型、参数、Prompt 版本、输入快照哈希、证据 ID、输出版本、Token 用量、耗时和错误类型。
- 原始外部响应不得包含密钥；日志不记录完整用户笔记。
- AI 报告可以追溯到输入证据，但不暴露模型隐藏推理过程。

### 5.9 FR-9 单股解释入口

- 详情页新增“解释当前结论”，输入固定为当前激活批次的个股证据包。
- 入口与“生成规则报告”并存；用户必须能明确区分确定性报告和 AI 解读。
- 无足够数据时解释数据缺口，不输出方向性结论。

### 5.10 FR-10 外部信息研究

- 搜索结果必须保存来源 URL、标题、发布者、发布时间、抓取时间、摘要和适用股票/行业。
- 最终报告必须把外部结论引用到具体来源。
- 来源不可访问、发布时间缺失或内容冲突时明确提示；不得只凭搜索摘要形成高置信度结论。
- 本模块不进入首期 P0 交付。

## 七、A/B 实验需求

暂无面向用户的 A/B 实验。当前为单用户工具，策略比较统一走离线 walk-forward 与影子策略，不使用随机流量分组。

## 八、验收标准

### 8.1 P0 验收

- 给定跨周末和节假日样本，T+1/T+3/T+5 均按有效交易日定位正确。
- 候选当日收盘后产生信号，评价参考价格不使用当日收盘价。
- 停牌、无报价、退市和批次缺失均生成可解释状态，不生成伪收益。
- 相同候选、horizon 和评价数据版本重复执行不产生重复记录。
- 回放任务无法读取验证窗口之后的数据，并通过未来数据泄漏测试。
- 未经批准的实验不能创建或激活生产规则版本。
- 策略效果页面所有统计可追溯到候选明细。

### 8.2 P1 验收

- 市场环境快照与 `data_batch` 一一关联，缺失字段有原因。
- 未配置或关闭 AI 时，现有报告、筛选、提醒和同步完全不受影响。
- AI 输出缺少证据引用或出现禁用表述时校验失败，不进入成功报告。
- Provider 超时、限流、格式错误和预算耗尽均返回明确错误，并支持安全重试。
- 历史 AI 报告展示生成时的模型、Prompt 和输入快照，不随设置变化。

## 九、风险与约束

- **样本偏差**：候选策略可能受股票池和市场阶段影响，必须显示样本量和分段结果。
- **未来数据泄漏**：任何回放读取未来批次都会使结果失真，列为阻断验收项。
- **数据源修订**：历史前复权可能变化，评价使用不复权价格并保留数据版本。
- **LLM 幻觉**：结构化输出、证据绑定和禁用表述校验必须是代码约束，不依赖 Prompt 自觉。
- **成本与隐私**：AI 默认关闭，密钥不落库；只发送生成报告所需的最小证据。
- **产品误导**：页面继续固定展示投资免责声明，不把正收益占比称为胜率，不输出目标价。

# S/F Matrix

## 满意标准（S）

- S1：本地一条命令可启动前后端并完成 PRD 核心链路。
- S2：筛选、提醒、详情和报告读取同一指标与信号结果。
- S3：前后端独立目录、依赖和构建，契约可验证。
- S4：核心公式、状态机、幂等和失败路径均有测试。
- S5：远程部署只需配置环境与数据库，不重写业务代码。
- S6：用户看到的是完整工具界面和真实交互，不是静态占位页。

## 失败模式（F）

- F1：只完成工程壳或静态页面，却声称实现 PRD。
- F2：前端和报告各自计算指标，导致结果不一致。
- F3：同步失败覆盖有效数据，或重试产生重复提醒。
- F4：测试只覆盖 DTO/健康检查，核心路径无断言。
- F5：本地可跑但代码耦合 SQLite/Vite，无法远程部署。
- F6：依赖真实 AkShare 才能测试，网络不稳定导致默认测试不可重复。

## Value Targets

| 编号 | 来源 | 高价值原因 | 优先级 |
|---|---|---|---|
| V1 | S1,S2,F1,F2 | 决定核心业务是否真实可用 | P0 |
| V2 | S4,F3,F4,F6 | 决定结果可信和可持续开发 | P0 |
| V3 | S3,S5,F5 | 决定隔离与部署能力 | P0 |
| V4 | S6,F1 | 决定用户可见交付质量 | P1 |
